PERSON 1

Data, Computer Vision & Optical Normalization

24-hour hackathon • Deliverable implementation plan • Source-aligned to Anemia Screening Hackathon Project Guide

Operating principle: fork-and-graft the existing RAHULPATEL2002/anemia-detection Flask application; do not rebuild the full stack from scratch.

Mission

Deliver a reproducible, leakage-aware dataset pipeline and a deterministic image-normalization module that reduces lighting and surrounding-skin/camera effects before model inference. Own the data and preprocessing workstream; do not modify the Flask UI or model architecture without agreement.

Source-aligned requirements

Use the guide’s recommended datasets: CP-AnemiC V2 (conjunctiva), EYES-DEFY-ANEMIA (conjunctiva; includes Indian and Italian cohorts), and Ghana Fingernails (nail-bed images). The Kaggle conjunctiva/nail Hb tables are an optional tabular baseline if available.

Use patient-level splitting, targeting 70% train / 10% validation / 20% test, and audit duplicate/augmented-image leakage before splitting.

Implement the guide’s order of operations: ROI isolation/cropping and glare masking → Grey-World white balance → HSV Value-channel CLAHE → CIE LAB ITA calculation and colorimetric feature extraction.

Do not assume these transformations alone prove fairness or clinical validity; provide measurable outputs and document failure cases.

Implementation checklist

Create a clear function boundary such as normalize_image(image, body_part) returning normalized_image, feature_vector and metadata. Confirm the exact signature with Person 2 before coding.

Keep feature order stable and document units/ranges; handle missing ITA or missing masks explicitly rather than silently inventing values.

Add tests for unreadable files, tiny/incorrect dimensions, glare-heavy images, grayscale/incorrect color channels and unsupported body-part values.

Retain original image and normalized image separately for the UI’s visual inspection panel.

Record whether each dataset has patient identifiers and laboratory Hb labels; do not infer missing ground truth from image appearance.

Acceptance criteria

A clean command or test can load a sample image and produce a normalized image plus documented features.

Train/validation/test assignment is patient-level; duplicates/augmented copies are checked and no known patient crosses partitions.

The pipeline demonstrates raw and normalized examples and logs failure/warning cases.

No preprocessing output is represented as proof of anemia or as a validated Hb estimate.

Definition of done and handoff

Commit working code to the agreed branch and include a short README section with setup/run instructions.

Provide one reproducible test or example input and record observed output; never label mock output as a real model result.

Tell the integration owner what is implemented, what is incomplete, known limitations, and exact files changed.

Do not claim clinical diagnostic performance without evaluation against laboratory-measured hemoglobin and a leakage-safe test set.

Scope guardrails from the source guide

Do not build a native Android/iOS app; use the existing mobile-responsive web application.

Do not train U-Net/Mask R-CNN from scratch, attempt INT4 quantization, train GAN/diffusion augmentation, or deploy PyTorch inference as Vercel serverless functions.

Treat dual-modality eye+nail fusion, the high-sensitivity toggle, leakage audit badge, and PWA as stretch goals only after the end-to-end core works.

The system is a screening aid/prototype, not a substitute for confirmatory CBC testing or professional clinical judgment.
